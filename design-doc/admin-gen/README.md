# Regenerating AlarmProcessor

`src/test/java/com/telamin/mongoose/replay/generated/AlarmProcessor.java` is generated by the hosted Fluxtion generator
from `AlarmNodes` (in the same test package) and `AlarmProcessorBuilder` (here). Mongoose's build has no builder, so
the generation runs in this small project:

1. `mvn -q install -DskipTests` in the repository root (the nodes need Mongoose's admin types).
2. Copy `src/test/java/com/telamin/mongoose/replay/generated/AlarmNodes.java` into this project's
   `src/main/java/com/telamin/mongoose/replay/generated/`.
3. `mvn -q process-classes` here. This needs a Fluxtion API key (`~/.fluxtion/fluxtion.apiKeyFile`): the scan calls the
   cloud generator. The pairing is builder 1.0.71 with runtime 1.0.16, as the analyser's fixture generator holds it.
4. Copy the generated `AlarmProcessor.java` into the test package **without the generator's copyright header**:
   everything before `package`. `GeneratedAdminAuditTest#theGeneratedSourceIsPublishable` fails if it comes back.

## Regenerating CycleAlarmProcessor (the 1.1.0 fixture)

`CycleAlarmProcessor` is the same graph generated by a builder that emits `runInEventCycle` (builder 1.0.76, runtime
1.1.0), so a lambda admin command runs as its own event cycle (`GeneratedCycleAdminAuditTest`). `AlarmProcessor` must
stay a pre-1.1.0 fixture (the audit-bracket fallback), and a scan runs every builder in the project, so generate this one
from a copy that holds only its builder:

1. Steps 1 and 2 above.
2. Copy this directory, delete `AlarmProcessorBuilder.java` from the copy, and in the copy run
   `mvn -q process-classes -Dfluxtion.version=1.1.0 -Dfluxtion.builder.version=1.0.76` (the same API key).
3. Copy the generated `src/main/java/.../CycleAlarmProcessor.java` into the test package without its header, as in
   step 4; `GeneratedCycleAdminAuditTest#theGeneratedSourceIsPublishable` checks it, and that it is a 1.1.0 processor.
