## Findings (most severe first)

1. HIGH, test-evidence. A rule that performs its effects but never replies is invisible to the harness, the invariant validator and the chaos oracle. ControlDriver's safety net answers FAILED "no reply after its effects settled" and writes a fallback FAILED record; ControlInvariants (src/test/.../validation/ControlInvariants.java:24, 84-93) accepts any FALLBACK_REPLIES record as "the reply" without reading its reason, ChaosWorkload (ChaosWorkload.java:873-895) only counts FAILED/REFUSED/NOT_RUNNING stops, and ControlScenarioHarnessTest discards stop ControlRequests (l.219, 232). Mutation (LifecycleRules.java:260-265 stopComplete without Reply): harness 205/205 pass, invariants verified, 10 s chaos pass with 113 FAILED stops. Fix: treat driver safety-net fallbacks (reasons "no reply after its effects settled", "effects did not settle", "control processor threw", "abandoned") and Anomaly/Dead records as violations; make the harness record every request it sends and assert each reply is APPLIED or a by-design refusal.
2. HIGH, test-evidence. I15 and I8 cannot see "reply before its effects' outcomes". ControlInvariants.java:66 skips records with cleanup:true, but that flag is set by the engine (EffectOutcomes.java:68) whenever the chain is already closed, and the Reply closes the chain. I8 (ControlInvariants.java:175) only flags failures with seq below the reply. Mutation (released() requests Reply(APPLIED) before ReleaseName): harness 204/204, regression 3/3, invariants silent; only the golden rule-sequence assertion caught it. Probe InvariantVacuityProbesTest.replyBeforeItsEffectsOutcomeVerifies shows APPLIED then "Release failed, cleanup:true" verifies. Fix: exempt only effects whose requesting Decision seq is after the reply; flag any failed non-cleanup effect of an APPLIED request.
3. HIGH, test-evidence. An APPLIED stop that never releases is not caught by the harness ledger (ControlScenarioHarnessTest.java:311-326 only bounds callback counts and start implies teardown, which the eventual group close satisfies). Mutation (onStop STARTED replies APPLIED, no Release): 177/205 seeds pass; the 28 failures came only from I1 keying on the Decision rule name "stopStarted" (ControlInvariants.java:210). Probe appliedStopWithoutReleaseVerifies: full trace verifies. Fix: ledger asserts every bound stop answered APPLIED has its processor stopped and torn down and its name released before group close; add an invariant that a stopStarted/closeGroup Decision requests Release and the APPLIED reply follows Release and ReleaseName outcomes.
4. MEDIUM, engine (replay). A replayed processor stopped live mid-stream makes complete() true and stopped() null. GroupReplayer.detach (src/main/.../replay/GroupReplayer.java:164-186) records an ended reason only for a stopped cursor, pending expected calls or stop reads; a cursor with undelivered entries is dropped by cursors.removeIf. Contract: "complete() with a null stopped(...) means every entry was delivered". Repro ReplayCursorDetachedMidStreamTest fails (two entries undelivered, complete=true, stopped=null). Fix: when !c.done(), put an ended reason such as "left the group at entry N of M before its replay completed".
5. MEDIUM, engine (replay). The documented status API (replayers().get(g).complete()/stopped()) is not safe off the agent thread: cursors is a plain ArrayList (GroupReplayer.java:33) iterated by complete/stopped/replays (l.351-356, 398-412) while the agent thread adds/removes cursors; Cursor fields are non-volatile. Repro ReplayStatusApiConcurrencyTest fails (ConcurrentModificationException/NPE within 1.5 s). ChaosReplayStressTest's poll loop (l.154-160) has no guard, so the "358,952 lines matched" run could fail spuriously on a boot-time attach. Fix: CopyOnWriteArrayList plus volatile next/stopped/ended, or publish an immutable status snapshot per doWork.
6. MEDIUM, engine (services). RemovedService.stop() checks supersession only under the OLD name (MongooseServer.java:988-989). Interleaving: register A=X; removeService(A) waits for a group whose @ServiceDeregistered handler is slow; meanwhile registerService(B=X) succeeds (retirement not yet claimed) and the group is handed X under B; the handler returns, the withdrawal is confirmed, and X.stop() runs while X is live under B. Violates "A service is never stopped while a processor that was given it may still hold it". Repro RetirementOtherNameProbeTest fails (expected 0 stops, was 1). PR-introduced (base stopped synchronously at removal). Fix: supersession = any live registration whose instance() is the same object; or refuse re-registration of an instance with an unconfirmed retirement.
7. MEDIUM, engine (capture, unrouted/direct embedding only; not reachable through MongooseServer because the router is set). processorStopped(group,name,flow) (ChronicleAuditCaptureService.java:506-510) falls through to the legacy processorStopped(name,flow) (l.536-543) which calls stop(name); stop resolves by bare name and, after gen1's binding was removed, uniquely finds gen2's scoped sink, ends its recording, restores the listener and closes a queue the group still owns. Repros ChronicleCaptureEdgeTest.retiringAnOldGenerationMustNotStopTheNewGenerationsCapture and ChronicleGroupInlineTest.replacementGenerationWithoutServerLeavesRetiredBindingAttached fail. Fix: only fall through when a standalone binding exists for that exact flow; make legacy processorStopped end only sinks.get(name) via endRecordingIfGone.
8. MEDIUM, test-evidence (independence). The harness relies on the engine's own outstanding() (ControlScenarioHarnessTest.java:342) and the audit, so a request silently dropped after claim is invisible unless incidental (mutation dropping 1/7 stops: 198/200 pass). ControlDriver.sweep had zero deterministic invocations across harness and regression runs. Anomaly, Dead, CaptureOrphan and abandoned-effect records are never violations (probe anomalyAndDeadFallbackRecordsVerify: a dead group's export verifies). Fix: harness keeps every ControlRequest and asserts reply().isDone(); add a sweep-exercising scenario; make engine-declared anomalies violations.
9. MEDIUM, test-evidence (coverage). Lifetime capture leaks are masked: a stale open never closed by the control processor is closed by releaseLeftoverCaptures at group close (ComposingEventProcessorAgent.java:1076-1110), whose offline fallback records satisfy I4 (mutation: 9 stale opens, 205/205 pass). The bundled chaos export (seed 19796) contains no failed closes/uninstalls, timeouts, NotRunning, Dead or Anomaly records and exactly one Release per closeGroup, so I1, I4-failed-close, I7, I11, I12-offline, I14, I16 are vacuous on it; the harness injects only failCloses/rejectNextOpen/rejectNextClose (l.268-270), never failed uninstall/open/install. Fix: assert captureResourcesHeld()==0 and zero offline records before close in harness/chaos; extend fault injection.
10. LOW-MEDIUM, engine (replay). A recorded start() failure consumes a stream ordinal (ComposingEventProcessorAgent.java:768) but records nothing (catch at 787-790 never tells the recorder); the stream holds provenance only. In a replay where start() succeeds, cursor p completes at once, the re-add becomes p#2 and is never attached, the processor receives a live service, and complete()=true with stopped()=null. Repro RecordedStartFailureReplaysAsSuccessTest fails. Fix: write a Failed marker for a recorded flow whose start threw, so replay stops at "the recorded run failed here".
11. LOW, engine (capture reporting). A failed post-release detach retry in the CloseCapture effect (ComposingEventProcessorAgent.java:988-1010) correctly retains the handle and slot, but captureCloseFailures() (l.410-416) stays empty, CleanupPending reports failedPhysicalCloses 0 with captureResourcesLeft 1, and CaptureRules removes the resource from the control table while the agent still holds it. Repro ChronicleGroupInlineTest.failedDetachRetainsSlotButIsNotListedAsCloseFailure (passes = confirmed). Fix: record the detach failure on the permit; do not removeResource while the handle is held.
12. LOW, compatibility/doc. ReplayEntry is sealed (replay/ReplayEntry.java:21) and gained Stopped/ServiceChanged/ControlCall; CsvReplayStore gained kinds STOPPED/SERVICE/CONTROL and a BEGAN line, so exhaustive switches in third-party code stop compiling and older builds cannot read new recordings. Release notes claim only backward read. ComposingEventProcessorAgent changed four public methods from void to ControlRequest (binary incompatible, not noted). Fix: document; note @Experimental.
13. LOW, doc vs code (plugins). control-plane-contracts.md:562-567 states selector and ambiguity semantics for start/stop/isRecording unconditionally, but only ChronicleAuditCaptureService.selectedSink implements them; a name-keyed plugin inheriting the scoped defaults (MongooseAuditCaptureService.java:98-109) aliases across groups and receives "g%2Fa/p" selectors it cannot resolve. A custom CaptureRouter without sendScoped silently loses auditCapture.autoStart (startScoped at ChronicleAuditCaptureService.java:237-243 calls the throwing default; server logs a warning). Fix: qualify the contract to the built-in service; document autoStart behaviour.
14. LOW, hardening and doc nits. attachScoped (ChronicleAuditCaptureService.java:245-254) refuses duplicate identity but not a second identity on the same DataFlow (repro twoScopedIdentitiesOnOneFlowClobberEachOther); openQueue (l.735-765) leaves a capture dir and sidecar if the Chronicle build throws, contrary to "openCapture must close anything created before throwing"; processorDropped (MongooseServer.java:457) frees the name reservation during Release, before the FAILED reply, while the contract says only the control processor frees it; a suppressed replay withdrawal is always retained until shutdown though the contract implies release when the stream withdraws; MongooseServerController javadoc for registerService/startService/stopService lacks the new IllegalStateException while stopping; CsvReplayStore (l.212, 214) fails a recording closed on a newline in a ControlCall outcome.

## Verdict
Core control plane (admission, close/death, replies, shutdown, pool) held up under targeted attack. Not ready to merge as-is: fix findings 4-7 and 10, then strengthen the validator/harness (1-3, 8-9) and rerun chaos, soak and replay on the fixed commit, because the current "zero violations" evidence cannot distinguish several classes of bad engine behaviour from good. Release qualification remains open as the maintainers state (soak on final commit, Linux performance, overload policy).
