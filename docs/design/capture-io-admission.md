# Physical capture open admission

A capture open timeout settles the control command but does not cancel blocked file I/O. Each processor group therefore admits at most eight unresolved physical opens by default. `ComposingEventProcessorAgent.setCaptureOpenLimit(int)` changes that positive limit; reducing it prevents new opens until the outstanding count falls below it. A saturated open returns an audited `FAILED` outcome without submitting I/O. Its slot remains held across timeout/cancellation and is returned only when the physical helper completes or submission is rejected. Duplicate execution by a custom helper cannot return a slot twice.

The shared default opener additionally bounds execution across groups and servers to eight daemon workers and 64 queued opens. Saturation rejects submission and follows the existing failed-open outcome path. Idle workers expire after 60 seconds. Existing `CaptureIo` injection remains available for deployments requiring a different I/O execution policy; the group limit still applies. Cancelled timeout tasks are removed immediately from the shared timer queue.

The opener limits alone do not cover every capture resource or the closer queue; the resource budget below covers those hand-offs. A close failure is an attempted operation with an explicit failed outcome; it is not evidence that the underlying resource closed successfully. The test resource ledger records attempts, successes and failures separately.

If an open completes after its group ends, compensation records a fallback `EffectRequested` and `EffectOutcome` for `CloseCapture`. Its operation ID is `<requestId>.orphan-close.<resourceId>`, distinct from the open operation; `causeOp` names the open, and `requestId`, `resourceId`, outcome and any failure reason remain available to independent validators. The existing `CaptureCompensated` summary remains for compatibility. Duplicate delivery of a resource already handed to a closer is marked duplicate and does not request another physical close.

A separate physical-resource budget covers admitted opens until successful physical closure, including installed resources and closes queued behind a blocked closer. Its default is 1024 per group, configurable with `setCaptureResourceLimit(int)`. `captureResourceSlotsInUse()` reports usage. This prevents repeated start/stop operations from creating an unbounded close backlog. Failed opens and rejected submissions return their slot; timeout does not. Successful closure returns a slot once, including cleanup after a failed detach. A thrown physical close retains the opaque handle and slot, with its reason exposed by `captureCloseFailures()`: it is unknown whether the resource closed, so automatic retries would be unsafe under the adapter contract. Further admission eventually fails closed until the underlying problem is resolved; changing the limit is not proof of cleanup.

Cleanup outside the generated processor emits fallback `EffectRequested`/`EffectOutcome` records for `UninstallCapture` before closing. These carry `resourceId`, `generation: -1`, `offline: true`, a unique `group-detach.<id>.<attempt>` op and actual success/failure. A succeeding close names that detach with `causeOp`, allowing an independent validator to verify that an installed resource was detached before it closed.

Server shutdown remains incomplete while any physical resource slot is unresolved, including queued/in-progress closes and failed closes. A later shutdown attempt can complete after a pending close succeeds. Failed physical closes are reported and are not automatically repeated; audit-wide cleanup does not run concurrently over those resources.

The shutdown helper waits for pending physical work while the stop caller joins it with the existing shutdown deadline. Known failed closes end that wait immediately. Failed-detach work remains retryable through the existing cleanup path. A failed physical-close slot is permanently held for that group: there is no acknowledgment or automatic-retry API, and external adapter-specific recovery cannot silently certify successful closure.
